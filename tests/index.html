Checks automáticos (T4 acciones por fila · T5 head)

Corren solos al cargar la página. Necesitan DOM real, por eso no están en npm test.

    Qué verificar a mano

    1. Param. /blog/hola-mundo muestra slug = hola-mundo.
    2. Decodificado. /blog/café-con-leche muestra el acento, no %C3%A9.
    3. La estática gana. /blog/nuevo muestra el editor, no el post con slug nuevo.
    4. Sin match. /nada cae al 404.
    5. Keep-alive por path completo. Escribí algo en el input de un post, navegá a otro post y volvé: el texto sigue ahí, y cada slug conserva el suyo (son entradas distintas de la cache, no una sola compartida).
    6. Sin inyección. Andá a /tests/blog/<img src=x onerror=alert(1)>: tiene que verse como texto y no ejecutar nada.
    7. Prefetch (T6). Con HOM_DEBUG prendido, pasá el mouse por un link del menú: sale ⇢ prefetch … una vez. Pasá de nuevo por el mismo: no se repite. Tabulá hasta un link con el teclado: también prefetchea. Nota: en esta página las rutas no tienen loader, así que para verlo hay que registrar una con () => import(...).
