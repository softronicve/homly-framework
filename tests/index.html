Tests de navegador de homly.js

Estos checks necesitan un DOM real (ciclo de vida de Custom Elements, CSS, historial, eventos confiables) y por eso no viven en npm test (que corre en Node, sin navegador). La forma normal de correrlos es automática:

npm run test:browser

Eso abre cada archivo de abajo en Chrome (vía tests/run-browser.mjs + puppeteer-core, solo de desarrollo) y falla si algo se rompe. Esta página es el índice para abrir alguno a mano durante el desarrollo — cada uno corre solo al cargarlo y escribe su resultado en la consola (window.__homly_results).

  • lifecycle.html — ciclo de vida: mover/reordenar no filtra ni re-monta (CORE-1/ROUTER-1); desmontar mientras carga la plantilla no deja nada corriendo (CORE-11/ROUTER-6).
  • router.html — navigate() y homly:navigate, misma URL → replaceState, token de navegación, normalización de rutas, reintento tras un loader que falla, e.defaultPrevented, adopción de prerender por params.
  • styles.html — CSS con y sin soporte de @scope (fallback a selector anidado).
  • security.html — allowlist de esquema en data-bind-attr para atributos de URL, y denylist de on*/ srcdoc.
  • list-actions.html — una acción disparada desde una fila de data-for recibe el ítem de esa fila (y solo esa); reentrancia (is-loading ignora un segundo click); texto de carga que restaura nodos, no solo texto; data-action="constructor".
  • list.html — data-for anidado dentro de una fila; un campo que desaparece de un ítem se vacía; ítems null o con clave duplicada no rompen el render.
  • model.html — data-model por tipo de control: radios, number/range ('' → null), select multiple, grupo de checkboxes; null no se pinta como texto; atributos boolean con semántica HTML nativa.
  • head.html — Homly.head(): título, meta tags, canonical, JSON-LD, sin duplicarlos al repetir.
  • ssr.html — protocolo SSR: adopción de filas por data-homly-key, siembra de estado, límite de componente.
  • conformance.html — el oráculo del kit de conformidad: hidrata la salida de renderers/homly.php con 0 mutaciones.
  • dispatch.html — dispatcher 1.10: data-action="evento->acción", ctx.event/ctx.formData, preventDefault automático, host más interno, homly:action-error.
  • reconcile.html — reconciliación de data-for con LIS + moveBefore: cuenta operaciones DOM reales (swap de 1.000 filas = 2 movimientos).
  • csp.html — servida con style-src 'self': 0 violaciones con el modo de estilos compartido.

Para ver los logs del router mientras navegas a mano, abre la consola y pon window.HOM_DEBUG = true (o 'verbose') antes de cargar la página — nunca por ?homly-debug=verbose en la URL: ese nivel no expone valores de señales (ver DEBUG-1).
